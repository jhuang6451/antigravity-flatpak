Google Antigravity as a Flatpak

An unofficial Flatpak repository for Google Antigravity, signed with GPG. A scheduled workflow builds each new upstream release, and you update with flatpak update.

Download .flatpakref Install with commands View on GitHub

Install

You need Flatpak and the Flathub remote. Flathub provides the runtime.

Repository

Adds the repository once. After that, updates arrive with the rest of your Flatpak apps.

flatpak remote-add --if-not-exists antigravity https://jhuang6451.github.io/antigravity-flatpak/antigravity.flatpakrepo
flatpak install antigravity com.google.Antigravity
flatpak run com.google.Antigravity

.flatpakref file

Download the file and open it in GNOME Software or KDE Discover, or run the command below. It also adds Flathub for the runtime if you do not have it.

flatpak install antigravity.flatpakref
Download .flatpakref

Offline bundle

Download com.google.Antigravity.flatpak from the latest release. A bundle does not receive updates.

flatpak install com.google.Antigravity.flatpak
Open latest release

Update

Run this, or let your software center do it.

flatpak update com.google.Antigravity

Permissions

The default sandbox is wide. Three things to know before you install.

Your whole home directory

The app can read and write everything in your home folder, including ~/.ssh and ~/.gnupg. Antigravity's agents can do the same.

Commands on your host

org.freedesktop.Flatpak allows flatpak-spawn --host, which runs any command outside the sandbox. The sandbox is not a security boundary.

Your SSH agent

--socket=ssh-auth gives the app every key loaded in your agent.

Tighten or widen access

User overrides take precedence over the manifest. Run these in a terminal.

Tighten

With home removed, the app no longer sees ~/.gitconfig, ~/.ssh or tools in ~/.local/bin unless you add them back.

# Only one project directory instead of all of $HOME
flatpak override --user --nofilesystem=home --filesystem=~/Projects com.google.Antigravity

# Drop host command execution
flatpak override --user --no-talk-name=org.freedesktop.Flatpak com.google.Antigravity

# Drop the SSH agent
flatpak override --user --nosocket=ssh-auth com.google.Antigravity

# Undo every override
flatpak override --user --reset com.google.Antigravity

Widen

Docker socket access is equivalent to root on the host. The device=all line exposes every device node.

# /dev/kvm for QEMU and the Android emulator
flatpak override --user --device=kvm com.google.Antigravity

# USB and serial devices
flatpak override --user --device=all com.google.Antigravity

# External disks and other top-level paths
flatpak override --user --filesystem=/mnt --filesystem=/run/media --filesystem=/media com.google.Antigravity
flatpak override --user --filesystem=/srv --filesystem=/opt com.google.Antigravity

# Podman and Docker sockets
flatpak override --user --filesystem=xdg-run/podman com.google.Antigravity
flatpak override --user --filesystem=/run/docker.sock com.google.Antigravity

Known limitations

What does not work with the default permissions, and what to do about it.

  • DevicesNo /dev/kvm, USB or serial ports. Hardware flashing, adb over USB and hardware-accelerated emulators fail inside the sandbox.
  • Paths outside home/mnt, /media, /run/media, /srv, /opt and /var/www are not visible.
  • Container socketsThe Docker and Podman sockets are not visible until you grant access.
  • Hardcoded /home paths on Fedora AtomicYour home is /var/home/<user>. The /home symlink does not exist inside the sandbox, so /home/<user>/... fails. Use $HOME or ~.
  • Host toolsPrograms installed system-wide on the host are not on PATH. Tools under your home work. For the rest, use flatpak-spawn --host.
  • Built-in updaterNot tested inside the read-only app directory. Update through Flatpak and ignore in-app update prompts.
  • Architecturex86_64 only, because upstream publishes no other Linux build.
  • No upstream checksumsCI records the SHA256 of the tarball it downloads. That pins the build to those bytes but does not prove they match what Google intended to publish.
